02Do / Don't とアンチパターン高コスト領域の要点

領域別 Do / Don't

  • DO③ Out を理由付きで書く。境界はフォルダでなくリポジトリで割る
  • ✕③ とりあえず1リポジトリに全部入れて後で考える
  • DO④ 不変条件を先に。契約は純粋関数1本に閉じる（compute_excluded_regions）
  • ✕④ 計算を表示・保存・テストにコピーする
  • DO⑥ 配布は制約。実装より先にOS・入手・同梱を書く
  • DO⑦⑧ 片道ドアだけ慎重／両開きは即決。一気に乗り換えない

アンチパターン（やりがち順）

  • ✕全部を1リポジトリ → 後でリブランド・分離
  • ✕契約の暗黙化 → 経路ごとに解釈がずれてバグ
  • ✕テストが本番をコピー → 本番バグを検知できない
  • ✕配布を最後に → パッケージング地獄
  • ✕完璧主義で着手できない → 全マスを埋めようと麻痺
  • ✕大きすぎるコミット → 物語が潰れ後で追えない
  • ✕決定の理由が消える → 同じ議論を繰り返す
0315秒セルフレビュー実装に入る直前に唱える

  2. 中核データの 不変条件 を一文で言えるか？
  3. これは 誰が・どのOSで 動かす？（配布制約を思い出す）
  4. いま増やそうとしているのは、Outに書いたものではないか？
  5. この判断の 理由 は、どこかに文章で残っているか？

すべてYesなら書き始めてよい。1つでもNoなら、そのマスに戻る。
