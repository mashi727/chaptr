# カリキュラム構成案 — 「上流設計：コードを書き始める前に決めること」

> 主題は **上流設計（着手前の意思決定）**。`course/00-上流設計の教科書.md` の10領域・12章立てをUdemyのセクション/レクチャーに落としたもの。
> Chaptrは**題材（case study）**。各章で「原則 → Chaptrの実際（決め損ね）→ 代償の実データ → 理想（上流で決めていたら）→ 自分のキャンバスに書く演習」を回す。
> 想定尺：**モードB（標準）≒ 3時間**。制作方針の3モードは末尾参照。
>
> ※旧版は開発年表をなぞる構成だった。本版で上流設計中心に全面改訂。年表版は `course/01`（証拠カタログ）として残置。

---

## コースのコンセプト

**タイトル案（3案）**
1. 「上流設計の教科書 〜コードを書く前に決める10のこと〜」
2. 「作り始める前に勝負は決まっている：設計思想の立て方」
3. 「AI時代の上流設計：CLAUDE.mdに落とす意思決定の技術」

**サブタイトル**
> プロジェクトが破綻するのは"書き方"ではなく"決め損ね"から。実在アプリの成功と失敗の両方を証拠に、着手前の意思決定を1枚のキャンバスに落とす。

**ターゲット受講者**
- 個人開発・小規模チームで「作り始めたら詰まる／作り直しになる」を繰り返している人
- コードは書けるが、設計判断（スコープ・分解・配布・命名）で毎回迷う人
- AI（Claude Code等）を使うが、指示の前提＝設計思想の作り方を知りたい人

**受講者が得られるもの（"What you'll learn"）**
- 着手前に埋める「上流設計キャンバス」10領域を自分のプロジェクトで運用できる
- スコープ・データ契約・配布・命名などの意思決定を、可逆性で仕分けて判断できる
- 「決め損ね」がどんな代償になるかを、実プロジェクトの証拠で理解する
- 設計思想を CLAUDE.md と判断ログ（worklog）に外在化し、AIと協働できる

**このコースの主張（1行）**
> **決定を、コードでなく文章で外在化せよ。**

**前提・非対象**
- ○ 対象：設計判断の考え方、上流設計の体系、AIとの協働設計
- × 非対象：特定言語/フレームワークの文法、実装のハンズオン（実装は題材の引用に留める）

## 収録の共通テンプレ（全レクチャー）

各レクチャーは5ブロック固定。実装コースの「実演」ではなく **意思決定の実演** が主役。

1. **原則（15秒）** — この回で決めること／キャンバスのどのマスか
2. **なぜ着手前か（30秒）** — 後回しにした時のコスト
3. **Chaptrの実際 → 代償（本体前半）** — `git show`・CHANGELOG・worklogで**証拠**を見せる
4. **理想：上流で決めていたら（本体後半）** — どう決め、どう書けば避けられたか
5. **キャンバス演習（締め）** — 受講者が自分の1マスを埋める課題

> ケース分析回は「証拠 → 反実仮想（if）」の型。実装画面は"証拠"としてだけ映し、手順の実演はしない。

## 各章の作りの型（再掲・重要）

すべての★ケース章はこの型で統一する：

```
原則の提示（座学）
   ↓
Chaptrの実際 ＝ 決め損ね（git show / CHANGELOG / worklog で"証拠"を映す）
   ↓
代償の実データ（改名100ファイル / 15コミット / 1pxバグ 等、数字で見せる）
   ↓
理想 ＝ 上流で決めていたら（反実仮想：どう書けば避けられたか）
   ↓
キャンバス演習（受講者が自分の1マスを埋める）
```

**証拠の映し方**
- `git show <hash> --stat` で規模を、本文diffは要点だけ。CHANGELOGの該当エントリと突き合わせる。
- worklogは該当章（5/27・6/3）で全画面表示し、「実際のセッションの思考」を読ませる。
- 実装コードは**契約や分解を語る証拠**としてのみ映し、手順の実演はしない（これは実装コースではない）。

## 制作モード（尺の3段階）

| モード | 内容 | 尺 | 向き |
|---|---|---|---|
| **A. 講義純度** | キャンバス＋Chaptr事例のみ、演習は課題提示だけ | 約2.0h | 密度最優先・最速リリース |
| **B. 標準（推奨）** | 上の全13セクション、各章末に記入演習 | 約3.2h | バランス。まずこれ |
| **C. ワークショップ** | B＋2つ目の題材を受講者と一緒にキャンバス設計する回群 | 4〜5h | 実践力最大・制作コスト大 |

**推奨導線**：まず **A（2h）で最小構成をリリース**して反応を見る → ★の3ケース章（4・5・7）を厚くして **Bへ拡張** → 要望があれば **Cのワークショップ回を追加販売**。
概念コースは尺より密度が価値。長くするより、★ケースの証拠の説得力に投資する。

## 旧「年表」構成との関係（移行メモ）

- `course/01-開発ストーリー.md`：破棄せず **「証拠カタログ」** として残す。各ケース章が引く `git show` 対象・worklog・数字はここから拾う。
- `course/03-台本サンプル.md`：旧年表の台本が混在。**上流設計版の台本は、Section 4/5/7 の★ケース章から作り直す**のが優先（次の作業）。旧L2.4等の実装実演台本は、本コースでは「証拠映写」の素材に格下げして流用。
- `course/04-リポジトリ整備.md`：タグ設計は本版でも有効（証拠に飛ぶ用途）。演習は「実装課題」から「**キャンバス記入課題**」へ差し替える。
