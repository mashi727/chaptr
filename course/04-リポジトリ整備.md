# 教材用リポジトリ整備ガイド

> 受講者が「各段階のコードに `git checkout` で飛んで、追体験できる」状態を作るための手順。
> タグ設計・演習課題・README導線・収録用の再現手順をまとめる。

---

## 方針：既存の履歴は壊さない

Chaptrの `main` はすでに公開済みの実履歴。**改変せず、タグとブランチを"上に乗せる"**だけで教材化する。
受講者にはリポジトリを clone してもらい、`git checkout <タグ>` で各段階に飛んでもらう。

- ✅ 既存52コミットはそのまま（本物の履歴＝信頼性）
- ✅ タグは注釈付き(annotated)で「このセクションの状態」を指す
- ✅ 演習の「途中まで」状態は専用ブランチで提供
- ❌ rebase / squash で歴史を作り直すのはしない（本物の泥臭さが教材価値なので）

## タグ設計：セクション → コミットの対応表

各セクション終了時点の状態に、注釈付きタグを打つ。命名規則は `course/s{セクション}-{スラッグ}`。

| タグ | 指すコミット | 状態（このタグをcheckoutすると見えるもの） |
|---|---|---|
| `course/s2-mvp` | `646a307` | MVP完成：3タブGUI・D&D・エクスポート・除外チャプター |
| `course/s2-dnd-before` | `0ae25b8` | D&D修正**前**（L2.4の出発点、event filter前） |
| `course/s2-dnd-after` | `5612154` | D&D修正**後**（DropOverlay適用済み） |
| `course/s4-macos-dist` | `a04954f` | macOS配布完成：ffmpeg同梱・GH Actions・DMG |
| `course/s5-windows-dist` | `800c6f5`※ | Windows配布完成：Nuitka・yt-dlp分離（PR#1マージ点） |
| `course/s6-architecture` | `1f54b9e` | 責務分割＋テストスイート着地後 |
| `course/s7-bug-before` | `01ef476` | 除外ハッチングのバグが**残っている**状態（デバッグ実演の出発点） |
| `course/s7-bug-after` | `ea120d3` | バグ修正後（compute_excluded_regions導入） |
| `course/s8-final` | `23edd5e` | 最終形（濁点NFC・高速化・回転まで） |

※ `800c6f5` はマージコミット。分かりにくければ `2693315`（yt-dlp bundle）を指しても可。

### タグを打つスクリプト

```bash
# リポジトリ直下で実行。既存タグがあれば -f で上書き。
git tag -f -a course/s2-mvp          646a307 -m "Section2完了: MVP（動くGUI）"
git tag -f -a course/s2-dnd-before   0ae25b8 -m "L2.4 出発点: D&D未修正"
git tag -f -a course/s2-dnd-after    5612154 -m "L2.4 完了: DropOverlay"
git tag -f -a course/s4-macos-dist   a04954f -m "Section4完了: macOS配布"
git tag -f -a course/s5-windows-dist 800c6f5 -m "Section5完了: Windows配布"
git tag -f -a course/s6-architecture 1f54b9e -m "Section6完了: 責務分割+テスト"
git tag -f -a course/s7-bug-before   01ef476 -m "Section7 出発点: 除外ハッチングのバグあり"
git tag -f -a course/s7-bug-after    ea120d3 -m "Section7 完了: バグ修正"
git tag -f -a course/s8-final        23edd5e -m "Section8完了: 最終形"

# タグをpush（受講者が取得できるように）
git push origin --tags
```

> ⚠️ このスクリプトは**リポジトリにタグを追加**する（履歴自体は変えない）。実行してよければ動かす。取り消しは `git tag -d <name>` と `git push origin :refs/tags/<name>`。

### 受講者向けの使い方（READMEに載せる文面案）

```bash
git clone https://github.com/mashi727/chaptr.git
cd chaptr
git tag -l 'course/*'              # 各段階の一覧
git checkout course/s2-mvp         # MVP完成時点に飛ぶ
git checkout course/s7-bug-before  # デバッグ演習の出発点に飛ぶ
git checkout main                  # 最新に戻る
```

## 演習課題（各セクション末）

受講者が手を動かす課題。「答えのコミット」を先に用意しておけるのがこのリポジトリの強み。

| セクション | 課題 | ヒント/答え |
|---|---|---|
| S1 | 自分のプロジェクト用のCLAUDE.mdを4ブロックで書く | 実物の`CLAUDE.md`を参照 |
| S2 | キーボードショートカットを1つ追加（例：`Home`で先頭へ） | `keyPressEvent`周辺 |
| S3 | 除外区間の色をプリファレンスで変えられるようにする | `waveform.py` paintEvent |
| S4 | GitHub Actionsに「lintジョブ」を1つ足す | `.github/workflows/` |
| S5 | Linux向けビルドジョブを追加してみる（発展） | release.yml、AppImage等 |
| S6 | `SubtitleManager`を読み、責務を1文で説明する | `managers/subtitle_manager.py` |
| **S7** | **`course/s7-bug-before`をcheckoutし、自力でバグを特定→修正** | 答え=`ea120d3`のdiff |
| S8 | 焼き込みタイトルに影(shadow)を付ける | drawtextの`shadowx/y` |
| S9 | CLAUDE.mdの「mpv統合」を設計提案としてまとめる | CLAUDE.md将来の検討事項 |

**S7が目玉演習**：バグのある状態(`s7-bug-before`)を配り、受講者が自分のClaude Codeで解く。
`worklog/2026-05-27.md` を「模範解答の思考プロセス」として後から見せる。
「同時刻の重複タイムスタンプ」で区間幅0になるチャプターデータ（下記）を演習用に同梱する。

演習用チャプターデータ（`course/exercises/s7-duplicate-timestamp.txt` として置く想定）:
```
# source: 演習用.mp4（末尾に同時刻の重複があり、先頭--の斜線が出ない）
0:00:00.000 --捨て
0:00:04.437 第1楽章
0:03:20.000 第2楽章
0:00:00.000 アンコール   ← 先頭 --捨て と同時刻で衝突（バグの原因）
```

## README への導線追加（案）

`README.md` の末尾（`## Contributing` の前あたり）に、教材リポジトリであることを示す節を足す。
既存READMEはアプリ紹介なので、**教材導線は独立した節**にして混ぜない。

```markdown
## 📺 このリポジトリで学ぶ（Udemyコース連動）

このリポジトリは、Claude Codeで実用アプリを作る過程を追体験できる教材を兼ねています。
`course/` に開発ストーリー・カリキュラム・台本、各段階に飛ぶ `course/*` タグがあります。

- 各段階へ: `git checkout course/s2-mvp` など（一覧は `git tag -l 'course/*'`）
- 教材の中身: [`course/`](./course/) を参照
- デバッグ演習: `git checkout course/s7-bug-before` で挑戦
```

## worklog 運用のドキュメント化（受講者への学び）

`worklog/` は既に実在し、**セッションをまたいで文脈を引き継ぐ**優れた実践例。
これ自体を「Claude Code運用術」の教材にできる。以下を `course/` の補足として案内する：

- worklog 1本の構成：TL;DR / やったこと / 成果物 / 触れたファイル / 重要な決定と理由 / ハマった点 / 実行コマンド / ユーザー指示 / 未完了・宿題 / 引き継ぎヒント
- 効能：次のセッションでClaudeに `worklog/最新.md` を読ませると、前回の文脈・未完了タスク・地雷（デッドコード等）を即座に共有できる
- コース Section 9.4 で実演：worklogを読ませてから作業を再開するデモ

## 収録者（あなた）向け：各レクチャーの再現手順テンプレ

収録時、各段階のコードを確実に再現するための手順。

```bash
# 例：L2.4（D&Dの罠）を収録する
git checkout course/s2-dnd-before   # 出発点の状態に
claude                              # 新規セッションで開始（前の文脈を持ち込まない）
# → 台本 course/03 の L2.4 に沿って実演
# 収録後 main に戻す
git checkout main
```

**注意点：**
- 実演で「Claudeに直させる」場面は、`s7-bug-before` のような**バグのある状態から**始めると自然。
- 最新の依存で動かない場合は、その段階の `uv.lock` / `pyproject.toml` に合わせて `uv sync` する。
- 収録用に作業ブランチを切ってもよいが、**教材タグは main 上のコミットを指す**ようにしておくと管理が楽。
