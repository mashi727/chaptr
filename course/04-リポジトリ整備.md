# 教材用リポジトリ整備ガイド（上流設計版）

> 上流設計コースは実装ハンズオンではないので、リポジトリの役割は**「追体験させる」ではなく「証拠を映す／演習の記入例を供給する」**。
> このガイドは (1) 証拠タグの設計、(2) 演習＝**キャンバス記入課題**の設計、(3) 収録手順、(4) 公開チェックリスト をまとめる。
>
> ※旧版は「各段階のコードにcheckoutして追体験」する実装コース前提だった。本版で上流設計版に改訂。

---

## 方針：既存の履歴は壊さない／リポジトリは「証拠庫」

Chaptrの `main` はすでに公開済みの実履歴。**改変せず、証拠タグを"上に乗せる"**だけ。
このコースでリポジトリが果たす役割は2つ：

1. **証拠庫**：ケース章（S4/S5/S7 等）で `git show`・CHANGELOG・worklog を映すための実物。**本物であること自体が信頼性の源**。
2. **記入例の供給元**：各章末のキャンバス演習で見せる Chaptr版の記入例（📋）の根拠。

- ✅ 既存52コミットはそのまま（本物の履歴）
- ✅ タグは注釈付き(annotated)で「そのケースの証拠位置」を指す
- ✅ 演習は**コードでなくキャンバス**。受講者はリポジトリを編集しない
- ❌ rebase / squash で歴史を作り直さない（決め損ねの痕跡こそ教材価値）

> 旧版にあった `s7-bug-before` を受講者がcheckoutして自力デバッグする"実装演習"は、上流設計版では**廃止**。
> 代わりに、そのバグは S5.3 で**証拠として映す**（受講者が触るのはキャンバス④）。

## 1. 証拠タグの設計：ケース章 → コミットの対応

各ケース章で映す証拠に、注釈付きタグを打つ。命名規則は `evidence/{章}-{スラッグ}`。
「追体験のチェックポイント」ではなく「**この章で映す証拠はここ**」という索引。

| タグ | 指すコミット | どの章で・何の証拠として映すか |
|---|---|---|
| `evidence/s4-monorepo-split` | `01ef476` | S4.3：スコープ決め損ね→100+ファイル改名の代償 |
| `evidence/s4-split-prep` | `fa70572` | S4.3：分離の下ごしらえ（依存を先に切る） |
| `evidence/s4-icon-lost` | `bac6ff9` | S4.3：境界引き直しの副作用（アイコン移行漏れ） |
| `evidence/s5-contract-bug` | `ea120d3` | S5.3：曖昧な契約→区間幅0バグの修正（純粋関数化） |
| `evidence/s6-arch-landing` | `1f54b9e` | S6.4：後付け分解＝7分9コミットの一括着地 |
| `evidence/s7-dist-nuitka` | `f62a81c` | S7.3：PyInstaller→Nuitka（Windowsのみ）の判断 |
| `evidence/s7-dist-dmgfix` | `a04954f` | S7.3：CIでしか出ない DMG Resource busy |
| `evidence/s8-tech-switch` | `f62a81c` | S8.3：全部を一気に乗り換えない選定 |
| `evidence/s11-rename-1` | `04da0b0` | S11.3：名前の揺れ①（rehearsal→media-scribe） |
| `evidence/s11-rename-2` | `01ef476` | S11.3：名前の揺れ②（→chaptr、スコープ確定と同時） |

> 配布地獄の連鎖（S7.3）は個別タグより **CHANGELOG v2.1.29〜2.1.34 の連続表示**が効く。タグは節目の `f62a81c`/`a04954f` だけでよい。

### タグを打つスクリプト

```bash
# リポジトリ直下で実行。既存タグがあれば -f で上書き。
git tag -f -a evidence/s4-monorepo-split 01ef476 -m "S4.3証拠: monorepo分離=100+改名"
git tag -f -a evidence/s4-split-prep     fa70572 -m "S4.3証拠: 分離の下ごしらえ"
git tag -f -a evidence/s4-icon-lost      bac6ff9 -m "S4.3証拠: リブランドでアイコン消失"
git tag -f -a evidence/s5-contract-bug   ea120d3 -m "S5.3証拠: 区間幅0バグ修正/純粋関数化"
git tag -f -a evidence/s6-arch-landing   1f54b9e -m "S6.4証拠: 7分9コミットの一括着地"
git tag -f -a evidence/s7-dist-nuitka    f62a81c -m "S7.3証拠: Windowsのみ Nuitka"
git tag -f -a evidence/s7-dist-dmgfix    a04954f -m "S7.3証拠: CIでしか出ないDMGエラー"
git tag -f -a evidence/s11-rename-1      04da0b0 -m "S11.3証拠: 改名1 rehearsal→media-scribe"
git tag -f -a evidence/s11-rename-2      01ef476 -m "S11.3証拠: 改名2 →chaptr"

git push origin --tags
```

> ⚠️ タグを**追加**するだけ（履歴は変えない）。取り消しは `git tag -d <name>` と `git push origin :refs/tags/<name>`。
> `evidence/*` は主に**収録者が証拠を素早く開く**ための索引。受講者にも「証拠を自分の目で確かめたい人向け」として案内できる。
>
> 📌 **push は自分の手元クローンから行うこと。** Claude Code on the web のセッション環境は、gitリレーが
> **セッション指定ブランチ以外への push（タグ含む）を 403 で拒否**する。上のスクリプトでタグは作れるが
> `git push origin --tags` は環境側で弾かれる。全9タグの対象コミット（`01ef476`/`fa70572`/`bac6ff9`/
> `ea120d3`/`1f54b9e`/`f62a81c`/`a04954f`/`04da0b0`）は検証済みなので、**このスクリプトをローカルで実行 → push** すれば確実に反映される。

## 2. 演習＝キャンバス記入課題（各章末）

このコースの演習は**コードを書くことではなく、上流設計キャンバスの1マスを埋めること**。
各章末に、受講者が「自分のプロジェクトの」該当マスを書く課題を出し、**Chaptr版の記入例（📋）を模範**として見せる。

| 章 | キャンバス領域 | 受講者の課題 | Chaptr記入例（模範） |
|---|---|---|---|
| S3 | ① 課題 / ② 成功条件 | 痛みを一文＋Doneの定義を書く | 「リハーサル動画→字幕SRTの配管ツール」／Done=章付き動画＋SRTが1本出る |
| S4 | ③ スコープ境界 | In/Out/Later を各3つ＋分割線 | In=編集〜出力／Out=LaTeXレポート(別repo)／Later=mpv統合 |
| S5 | ④ 中核データと契約 | 中核データ1つ＋不変条件3つ | チャプター（時刻昇順・同時刻可・区間は厳密に大きい次まで） |
| S6 | ⑤ 分解方針 | アプリを3層に素描 | 状態=managers／UI仲介=controllers／重処理=workers |
| S7 | ⑥ 配布制約 | 依存の同梱/要求＋配布形態要件 | ffmpeg同梱・非エンジニア向けスタンドアロン・コンソール非表示 |
| S8 | ⑦ 技術選定 | 主要技術1つ＋乗り換え条件 | パッケージャ採用、コンソール問題が構造的に残るなら乗換 |
| S9 | ⑧ 可逆性マップ | 決定を片道/両開きに2列仕分け | 片道=名前/データ形式／両開き=色/ショートカット |
| S10 | ⑨ AI協働 | 自分が握る判断を3つ | 課題定義・スコープ・前提データの提示 |
| S11 | ⑩ 名前 | 確定名を1つ決め⑧の片道側へ | chaptr（スコープ確定後に一度で決める） |
| S12 | 全体 | 10マスを1本のCLAUDE.mdに変換 | 実物 `CLAUDE.md` が到達点の見本 |

**演習の運用：**
- 受講者は**リポジトリを編集しない**。自分のプロジェクト（or 架空の題材）のキャンバスを埋める。
- 各章の📋記入例は Chaptr。「決め損ねた領域（③④⑥⑩）」ほど、実際は空欄だった→後で高くついた、という物語付きで見せられる。
- 記入用のテンプレと記入例を同梱する（下記）。

### 同梱する演習ファイル

| ファイル | 用途 |
|---|---|
| `course/exercises/上流設計キャンバス-テンプレート.md` | 受講者が埋める空テンプレ（10領域） |
| `course/exercises/上流設計キャンバス-Chaptr記入例.md` | 全10マスのChaptr記入例（模範／各マスに"実際は決め損ねた"注記） |
| `course/exercises/s5-duplicate-timestamp.txt` | S5.3で映す「区間幅0バグ」の実データ（旧s7データを改称） |

> 空テンプレとChaptr記入例は、コースの**持ち帰り成果物**そのもの。よりリッチな1枚絵にしたい場合は、別途アーティファクト化を検討（本ガイドの範囲外）。

## 3. README への導線追加（案）

`README.md` の末尾（`## Contributing` の前あたり）に独立節を足す。アプリ紹介とは混ぜない。

```markdown
## 📚 このリポジトリで学ぶ（上流設計コース連動）

このリポジトリは、Udemyコース「上流設計：コードを書き始める前に決めること」の題材です。
Chaptrの実際の履歴を"証拠"に、着手前の意思決定を1枚のキャンバスに落とす方法を学びます。

- 教材の中身: [`course/`](./course/)（`00`が背骨＝上流設計の教科書）
- 上流設計キャンバス: [`course/exercises/`](./course/exercises/) にテンプレとChaptr記入例
- 証拠を自分の目で: `git tag -l 'evidence/*'` で各ケースの該当コミットへ
```

## 4. worklog を「判断ログ」の実例として使う（⑨/§3(b)）

`worklog/` は、上流設計の最終要素**「決定の理由を記録し継承する（判断ログ）」**の生きた実例。
S10（AI協働）・S12（落とし込み）で参照する。

- worklog 1本の構成：TL;DR / やったこと / 成果物 / 触れたファイル / **重要な決定と理由** / ハマった点 / 実行コマンド / **ユーザーからの指示・好み** / 未完了・宿題 / 引き継ぎヒント
- 効能：次セッションでClaudeに `worklog/最新.md` を読ませると、前回の決定・理由・地雷（デッドコード等）を即共有できる＝**設計思想のgit history**
- S10.4 の証拠：`worklog/2026-05-27.md` の「AskUserQuestionを断り実データを渡した」くだり

> ⚠️ **公開前マスク必須**：worklog には作者のローカル絶対パス（`/Users/mashi/...`）が含まれる。
> 動画で映す前・リポジトリ公開前に、パスや個人情報をマスクすること。

## 5. 収録者向け：証拠映写の手順（追体験ではない）

このコースの収録は「コードを書く実演」ではなく「**証拠を映して語る**」。手順はシンプル。

```bash
# 例：S4.3（スコープ決め損ねの代償）を収録する
git show evidence/s4-monorepo-split --stat   # 100+ファイル改名の規模を映す
git show evidence/s4-icon-lost               # 副作用（アイコン消失）を映す
#  → CHANGELOG の該当節、worklog/2026-06-03.md も併せて画面に出す
#  → 台本 course/03 の S4.3 に沿ってナレーション
```

**注意点：**
- 証拠は**事前に開いておく**（本番で `git show` を打つなら打ち間違い対策にコマンドをメモ）。
- 数字（100+ファイル、README-207行、15コミット、1px）は**事実に忠実に**。Before/Afterスライドの数値は `--stat` と突き合わせて確認。
- worklog を映す回は**絶対パスをマスク**。
- コードは「契約・分解・代償の証拠」として映すだけ。ライブコーディングはしない。
