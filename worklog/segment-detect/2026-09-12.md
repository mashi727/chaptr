### 重要な決定と理由

1. **休憩を「非コヒーレンス」で定義する** — 合奏は全員が同一テンポで発音するので onset 包絡の自己相関にピークが立つ（pulse 0.29）が、非同期な個人練習では立たない（0.15）。12 秒窓のテクスチャ（crest・帯域内 DR）は合奏と休憩でほぼ同じで分離しない。
2. **乗算ゲートではなく重み付き和** — `steady × not_tutti × audible × incoherent` を試したが、どれか一つが揺らぐだけでスコアが消え、正解の休憩を取り逃した。`play`/`talk` と同じ重み付き和（0.30/0.30/0.20/0.20）にした。
3. **「静か＝休憩」の項を落とす** — カメラが指揮者から遠く、コメント中（−41 dB）の方が休憩（−27 dB）より静かで、無音床（−42.7 dB）すれすれ。この項が偽陽性 12 個の発生源だった。ユーザーがクリップ E を「指揮者コメント」と確認したことで裏付けられた。
4. **既定感度は `loose`（拾い目）** — ユーザー指示「どちらかというと、拾い目に倒しておきたいですね」。見逃すと 3 時間の録画を手で走査する羽目になるが、余分な候補はスキップ 1 回で消える。損失が非対称。
5. **合成素材を実態へ寄せる** — `make_break` が演奏の −37 dB（実質デジタル無音）で、「合成では通るが実素材で落ちる」構造だった。実測に合わせて演奏の 4〜6 dB 下へ上げ、全区間にホール暗騒音を乗せた。「休憩と演奏のレベル差が 15 dB を超えたら合成が甘い」ガードもテストに入れた。
6. **Chaptr に ASR を持ち込まない** — 実測で対話用途に不適と判明。既に持っている字幕を使う形なら追加依存ゼロ。字幕が無ければ下書きが出ないだけで挙動が変わらない。
7. **表題は素のテキストのみ** — 曲名・練習番号・小節の解釈は素材ごとの語彙に依存し、汎用の章立てツールが持つべきではない。ユーザーの懸念「ここまで作り込むと、プレイヤーとしての汎用性が損なわれますね」に対応。
8. **時刻編集の入口はダブルクリックのみ** — ユーザー指示。Enter →タイトル編集、タイトルのダブルクリック→シークは不変。
9. **初期タイトルは休憩優先** — `--` は除外区間に直結してそのまま使えるが、その位置の発話は「はい、10分休憩します」のような文になり表題としては劣る。

### 検討して採らなかった選択肢と理由

1. **定常性（swing）だけで休憩を分離** — 平滑化しても「静かな合奏」の方が休憩より定常（5〜10 対 10〜21）で、原理的に分離しない。合奏 tutti（swing 30.7）とは分離するので重み 0.20 で残した。
2. **オンセット包絡の尖度（kurtosis）** — 区間全体で測ると休憩 25.2 / 演奏 5.7 と大きく分離したが、20〜60 秒窓では全体が 3〜4 に潰れて分離しなくなった。長スパンの 4 次モーメントは稀な大イベントに支配され、頑健でない。
3. **スペクトル平坦度（flatness）** — 休憩 0.367 / 演奏 0.230 で分離するが、合奏 tutti が 0.421 とさらに高い（多楽器＝密なスペクトル）ので、合奏を排除できない。
4. **Add Chapter 都度の文字起こし** — ユーザー提案。実測で kotoba 35.6 s / wp 58.8 s（40 秒クリップ）。押してから 1 分後に候補が出るのでは使えない。候補全部を先回りしても、実素材のセグメントは 34〜68 個で 45 分ぶんの音声＝40 分以上かかる。
5. **カット前に全長を文字起こしし Chaptr が時刻を付け替える** — 一度は推奨したが、ユーザーの「SRT から起こすとワークフローからの制約を受けて、単独のアプリとしての汎用性を失いますね」を受けて撤回。最終的に「同名 SRT があれば使う、無ければ出ない」という依存ゼロの形に落とした。
6. **感度 `loosest` を既定にする** — 確認済みの合奏・演奏・コメント区間すべてに命中するため実用外。選択肢としては残した。

### ハマった点・エラーと回避策

1. **`git apply` の原子性を誤認** — `git apply -3` が `audio_cache.py` に「Applied cleanly」と出したのに `main_workspace.py` で失敗し、**両方ロールバックされていた**。`ImportError: cannot import name 'RegionSpectrogramWorker'` で発覚。ファイルごとに分けて適用して解決。

2. **`_refine_break_bounds` の伸長が元に戻る** — 休憩の端を前へ伸ばした直後、連続化ループ `if out[i].end_ms > out[i+1].start_ms: out[i+1].start_ms = out[i].end_ms` が前の区間の終端で上書きしていた。休憩側の境界を優先するよう分岐を追加。

3. **合成の失敗ケースで文脈窓が休憩より長い** — `break_context_sec=480` に対し休憩 420 秒。窓が必ず前後の演奏を含むので、休憩の内側でも swing が下がらなかった。180 秒（±1.5 分）へ短縮。

4. **パイプの `tail` で出力が見えない** — `python ... | tail -40` はパイプが閉じるまで何も出さないため、長時間実行の進捗が完全に不可視になった。「600 秒でハング」と誤認したが、実際はスクリプトのパス組み立てミス（`f"{sys.path[0]}/{name}"` に絶対パスを渡していた）。ファイルへリダイレクトして解決。

5. **Qt が abort する**
   ```
   Incompatible processor. This Qt build requires the following features:
       neon
   ```
   サンドボックスが `sysctl` を塞ぎ、Qt の CPU 機能検出が失敗していた。`dangerouslyDisableSandbox: true` で回避。

6. **パッチスクリプトの多重一致** — 挿入するヘルパー本体が置換対象と同じ行（`self._segment_status_label.setText(text)`）を含んでいたため、先に本体を挿入すると count が 2 になり assert で落ちた。呼び出し側を先に置換する順序へ変更。

7. **`srt-cap-spans` が短いクリップで失敗**
   ```
   srt-cap-spans: error: 発話速度を計測できません（短い cue が少なすぎる）。--rate で指定してください
   ```
   40 秒クリップでは cue が足りない。`transcribe-srt` は生 SRT へフォールバックするので実害なし。

8. **バックグラウンドへ移ったコミットが実行されない** — ヒアドキュメントを使った `git commit -F -` が 180 秒でタイムアウトしてバックグラウンド化し、そのまま落ちた。メッセージをファイルへ書いてから `git commit -F <file>` で解決。
