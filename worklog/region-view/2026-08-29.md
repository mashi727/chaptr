### 重要な決定と理由

- **ホバー単独では解決しない** — ホバーは「指している時刻の読み取り」を与えるだけで、1px=9秒という指示精度は変わらない。所望位置の抽出に手間取る原因は分解能なので、2段構成が必要。
- **メモリ常駐（ffmpeg 再抽出ではなく）** — ホバーは連続イベント。区間ごとに ffmpeg を起動すると プロセス起動30–50ms＋デコード100–400ms で 200–500ms かかり「ホバー」ではなく「読み込み」の体感になる。
- **採用レートは総RAMから決定的に、空きメモリは拒否権のみ** — 空きを主入力にすると同じ素材でも起動タイミングでレートが変わり再現性が失われる。macOS の available は圧縮可能・purgeable を含み過大報告する。空きは「スワップ突入の回避」という本来の用途に限定（`available < needed×3` で1段下げ）。
- **dB基準は全体から一度だけ決める** — 区間ごとに min/max を取り直すと、なぞるたびに明度が脈動し、無音区間ではノイズフロアがフルスケールまで持ち上がる。レンジは固定幅ではなく全体統計から（`clamp(p99.9 - p2, 30dB, 90dB)`）。固定70dBだとダイナミックレンジの狭い素材で全面が飽和した（合成信号で平均0.92）。
- **メルフィルタバンクは面積正規化＋窓エネルギー除算** — これがないと `n_fft` が変わったとき（拡大するほど窓が短くなる）dBの絶対値がズレ、拡大するほど暗くなる。
- **留め（pin）は再生位置より常に優先** — 解除は「上段クリック」と「再生が留めた区間へ追いついたとき」の2つだけ。
- **下段は寒色系（viridis）固定＋オーバーレイは反対色相** — 上段を Mel Spectrogram に切り替えると上下が同じ見た目になる。既存のオーバーレイ色（紺碧・常磐緑・勿忘草色）は inferno の暖色に対して選ばれた寒色なので、寒色マップ上では溶ける。
- **動画は右パネル幅いっぱいに16:9、余りを波形へ** — stretch で按分すると動画の縦横どちらかが必ず余る。幅を基準に高さを決めれば無駄が出ない。
- **YouTube削除の境界はダウンロード経路のみ** — チャプターのYouTube形式（`Copy to Youtube`、`.txt`出力、貼付けパース）は別機能なので残す。README の YouTube 記述はすべてこちら側だった。

### 調べて分かった外部仕様

- **`QVBoxLayout` は子ウィジェットの `heightForWidth` を十分に尊重しない**。サイズポリシーに `setHeightForWidth(True)` を設定しても最小高さで潰れる。`QGridLayout` 等と挙動が異なる。→ `resizeEvent` で実幅から明示的に `setFixedHeight` する必要がある。
- **子に `setFixedSize` するとレイアウト経由で親の最小サイズへ伝播し、stretch の取り分を上書きする**。動画コンテナを枠のレイアウトに載せたまま固定サイズにすると、波形との按分が壊れた（1400×900 で波形が 70/104 まで潰れた）。→ コンテナをレイアウトから外し手動配置（`setGeometry`）にして伝播を断つ。
- **macOS のトラックパッド/Magic Mouse はピクセル精度の `wheelEvent` を大量に送る**。イベント1個＝1段の実装だと一度の指の動きでラダーを端まで走る。Qt の作法どおり `angleDelta` を積算し閾値（標準マウス1ノッチ=120）で刻む。
- **`chaptr/ui/workers.py` と `chaptr/ui/dialogs.py` が同名パッケージの陰に隠れた旧モノリスとして残っている**（Python はパッケージを優先するため読み込まれない）。今回削除した YouTube クラスの旧定義もそこにある。
- **`chaptr.spec` の hiddenimports に `psutil` があるが `pyproject.toml` にも `uv.lock` にも無い**（既存の不整合）。クリーンな `uv sync` 環境では `import psutil` が失敗する。→ `audio_cache.py` では psutil があれば使い、無ければ stdlib（Windows: `GlobalMemoryStatusEx` via ctypes / macOS: `sysctl`+`vm_stat` / Linux: `/proc/meminfo`）へフォールバック。
- **サンドボックス内では `sysctl` が "Operation not permitted"、PySide6 が "Incompatible processor. This Qt build requires: neon" で落ちる**。GUI 検証は `dangerouslyDisableSandbox` が必要。
- 確認コマンド: `python -c "import chaptr; print(chaptr.__file__)"` で editable install が作業ツリーを指すことを確認できる（本機は editable）。

### 検討して採らなかった選択肢と理由

- **ホバー停止時に ffmpeg で区間を再抽出** — メモリ増なしでメル帯域も11kHz保てるが、200–500ms の遅延で「なぞる」操作にならない。
- **全長スペクトログラムを事前計算してパンするだけにする** — 50ms/列で3.5h＝252,000列。uint8 で32MBと軽いが、STFT に約30秒かかる。10ms/列まで細かくすると約150秒で非現実的。
- **ウィンドウ比を 4:3 に固定して動画エリアを16:9に保つ** — 実測では 4:3 上でのみ16:9近傍（ずれ −24〜+32px）に留まり有効だったが、動画コンテナ自体を16:9固定にした時点で不要になり、比率ロックごと撤去。
- **`heightForWidth` によるレイアウト折衝で動画枠の高さを決める** — 上記のとおり Qt が尊重せず、字幕パネルの表示切替でも値が揺れた。固定値での余白決め打ち（68px）も、字幕が既定で非表示のため誤り（その60pxがコンテナに回り16:9からずれる）。

### ハマった点・エラーと回避策

**1. 区間表示のちらつき（2つの独立した原因）**

- 原因A: `QTimer.start()` がマウス移動のたびにデバウンスを再起動していた。8–16ms間隔でイベントが来る間、40msが一度も満了せず、手が緩んだ瞬間だけ散発更新 → 飛び飛びの大ジャンプ。
- 原因B（**主因・ユーザーの診断が正しかった**）: `_sync_region_to_playback` で留めの判定を「再生位置が区間内のとき」のブロック**内側**に置いていた。カーソルを再生位置から離すと `inside` が偽になり、留めたはずの区間が再生位置へ引き戻される。ホバーがカーソル側へ、`positionChanged` が再生位置側へ、交互に奪い合う時分割。
- 旧ロジックを復元して再現を確認: 区間中心が `[100s(再生位置), 400〜404s(カーソル)]` を往復、**20回中10回引き戻し**。
- 対処: A=進行的精細化（移動中は列数1/4・行数1/2で即描画、停止120ms後に精細版）、B=留めを再生位置より常に優先。修正後は引き戻し0回、単調前進。

**2. `calibrate()` が全長を float32 展開してピーク1.6GB**

常駐530MBの意図を潰していた。→ 全体へ均等に散らした4000フレームだけ取り出す方式へ（ピーク約50MB）。

**3. `NameError: Error calling Python override of QFrame::sizeHint(): name 'QSize' is not defined`**

`main_workspace.py` の Qt import に `QSize` が無く `QSizeF` のみだった。

**4. `ImportError: cannot import name 'reset_ffmpeg_cache' from 'chaptr.ui.ffmpeg_utils'`**

`tests/test_ffmpeg_utils.py` の収集エラー。**HEAD から存在する既存不具合**（今回の変更とは無関係）。回帰確認では `--ignore` して比較した。

**5. `ModuleNotFoundError: No module named 'chaptr.ui.youtube_mixin'`**

YouTube削除後に `tests/test_youtube_mixin.py` が収集エラー。削除した機能のテストなので併せて削除。

**6. サイズ調整で3回外した**

スクリーンショットからの寸法推定に頼ったのが原因。「動画がめっちゃちっちゃくなりやしたぜ！」「全然ダメやね。」。特に「波形の高さを1つ前に戻す」を**大きくする**方向と読んだが、対象のスクリーンショットの波形は逆に小さく（上約70/下約104）動画が幅いっぱいだった。→ 最終的に「幅から高さを決める」方式で目標値を再現。

**7. `resizeEvent` の早期 `return` でコンテナが古い寸法のまま残る**

枠の高さは正しく 892×505 と計算できていたのに、高さを変えた回に `return` で抜けて `refresh_content_size()` を呼ばず、コンテナが 631×355 のままだった。
