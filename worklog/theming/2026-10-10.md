### 重要な決定と理由

- **pt ではなく px で置く。** 論理 DPI が macOS 72 / Windows 96 と異なり、同じ pt 値が Windows で 3 割大きく出る。`_sized()`（`app.py:83-91`）に、過去それで「`Mel Spectrogram` が固定幅ボタンから欠けた」と記録があった。19px 化の実測でこの不具合が**実際に再現**した（160px の枠に 171px 必要）。
- **一次資料の palette は改変しない。** solarized-light のパネル面が 4.4:1 で AA を 2% 下回るが、Solarized は低コントラストを意図した配色。テストに実測値つきの例外として明記する方を選んだ。
- **映像ステージの黒（`#0f0f0f`）は配色に追従させない。** レターボックスは暗い方が映像を正しく見られるため。テストの許可リストに明示。
- **死んだコード `_file_dialog_dark_style` は削除せずトークン化。** 2 ファイルで定義されどこからも呼ばれていない（直書き 52 色）。削除はユーザーの判断領域なので、将来配線されたときに暗色が復活しないようにだけしておく。
- **貼り直しはタグ方式。** ウィジェットに `setProperty("chaptr_style", <tag>)` を付け、`reapply_theme()` が `findChildren` で回して `_style_for(tag)` を貼り直す。スタイルシートは生成時に色を文字列へ焼き込むため、配色変更では貼り直しが必須。
- **`Colors.on_color()` はコントラスト最大化で選ぶ。** ルマの閾値で明暗を切ると中間の明るさ（one-light の `#4078f2`、ルマ 0.46）で誤った側を選ぶ。候補に純白・純黒も含める（配色内の色だけでは彩度の高い地で 4.5:1 に届かないことがある）。

### 調べて分かった外部仕様

- **base16 配色の一次資料**: `https://raw.githubusercontent.com/tinted-theming/schemes/spec-0.11/base16/<name>.yaml`。spec-0.11 形式（`system` / `name` / `author` / `variant` / `palette`、値は `#` 付き）は既存の `Base16Scheme.from_yaml` がそのまま読める。
- **base16 の名前は意味役割を保証しない。** `base08`（慣習的に赤）が紺のもの（tokyo-night-light `#343B58`）、`base06`（慣習的に明るい文字）が鮭色のもの（catppuccin-latte `#dc8a78`）、`base02`（選択）が `base00` より明るいものが実在する。採用前に機械判定が要る。
- **Qt の色は 2 系統で決まる。** スタイルシート（`QToolTip` / `selection-color` など）と `QPalette`。片方だけ指定すると、もう片方は OS 既定から来る。macOS はさらに**フォーカスを失った選択を `QPalette.ColorGroup.Inactive` の灰色で描く**ので、Active だけ設定しても足りない。本件では Active / Inactive / Normal の 3 グループに設定した。
- **確認方法**: ツールチップは `QToolTip.showText()` 後に `app.topLevelWidgets()` から `className() == "QTipLabel"` を拾って `grab()` できる。セル編集のエディタは `table.editItem(item)` 後に `table.findChild(QLineEdit)`。
- **`QLineEdit` の共通 `min-height` はセル編集で破綻する。** 表の行の高さを超えると編集枠が下の行に重なる。`QTableWidget QLineEdit { min-height: 0 }` で行に従わせる。
- Qt のオフスクリーンプラットフォームは論理 DPI **96** を返す（実機 macOS は 72 のことがある）。pt 指定の見た目は検証環境と実機で一致しない。

### 検討して採らなかった選択肢と理由

- **tokyo-night-light の同梱** — ユーザーが選んだ暗色 tokyo-night の対になるので第一候補だったが、`base08` が赤でなく紺で「削除ボタンが紺色」、`base02` が地より明るく「選択行が周囲より明るい」になる。記憶から palette を書いていたら気づけなかった（一次資料を取得して判明）。
- **catppuccin-latte の同梱** — 人気があり見た目も良いが、`base06`＝強調文字が鮭色で地との比 2.3:1。波形のマーカー色（`FOREGROUND_BRIGHT`）に使われるため実害が出る。
- **gruvbox-light-hard の同梱** — 既存 gruvbox-dark の対になるが淡色文字が 2.0:1。
- **font-size を pt で指定** — ユーザーは「14pt」と指示したが、pt のまま実装すると上記 DPI 差の不具合が戻る。選択肢の提示時に実測値（18.7px）を併記し、px で同じ見た目を出す方針に合意を得た。
- **`FOREGROUND_DIM` を ghost ボタンの文字色に使い続ける** — 明色テーマで 2.4:1 まで落ちて押せることが分からない。面を持たない分、字は本文色に。

### ハマった点・エラーと回避策

- **ツールチップの実描画測定で「全 8 配色が読めない」と誤判定した。** 2 番目に多い色を文字と見なしたため、実際には**枠線**（`base03`）を測っていた。現象: tokyo-night で `#16161e / #444b6a 2.1:1`。十分な画素数を持つ色のうち地から最も離れた色をグリフとする方式に変えたところ 11.2:1 となり、設定値と一致した。
- `AssertionError: (1, '        # ハイライト時のテキストは暗い背景かどうかで決める\n        highlight_fg = QBrush(QColo')` — 同一行が 2 箇所にあるがコメントは片方にしかなく、まとめ置換が失敗。書き込み前に停止したためファイルは無傷。行だけを置換してからコメント重複を外す手順に変更。
- `edit: editing failed` が 7 回 — 配色ループ内で `closePersistentEditor` を使ったため（開いたのは `editItem`）。2 回目以降エディタが開かず、枠線の色を測っていた。テーマごとにウィンドウを作り直す方式に変更。
- **表へ直接 `setItem` すると行がずれる。** 投入直後に読み戻すと `[None, '0:00:00.000', '0:00:35.571', '0:42:16.002']` と 1 行ずれて 1 件消える。`cellChanged` → `_on_chapter_edited` が走るため。本体の読み込み経路は `blockSignals(True)` してから書くので製品側の不具合ではない。**測定用の投入でも signals を止める必要がある。**
- **1200px 幅で撮影して「時刻が切れている」と誤認した。** ウィンドウ最小幅は 1316px で、それ未満に `resize()` すると内容が窓の外へはみ出して描画される。既定の 1400px では時刻もデバイス名も全部出る。
- `assert "{" not in css` — CSS には波括弧が当然あるので、置換の検証条件として不適切だった。`"Colors.get" not in css and "{{" not in css` に変更。
- zsh で `grep --include=*.py` がグロブ展開され `no matches found`。クォートが必要。
- シェル初期化が `ifconfig.me:443` へ出ようとしてサンドボックス違反が毎コマンド出る（動作には影響なし）。
