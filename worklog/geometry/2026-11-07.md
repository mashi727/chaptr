### 重要な決定と理由

- **比の選択肢（16:9 / 4:3 / 3:2）は作らず、入切のチェック 1 つにした。** 出力は入力フレームと同じ寸法で、四隅はその枠いっぱいへ写される。歪みが出ないのは「四隅の比＝出力の比」のときだけで、他の比は*意図的に歪ませる*指定になる。正解が 1 つしかないものを選ばせない。
- **寄せるのは指を離したとき**（`FrameCanvas.released` を `changed` と分離）。ドラッグ中に直すと掴んだ角が逃げて合わせられない。
- **常に内側へ詰める。** 広げると枠の外を舐めて黒が入る。横に広ければ横を、縦に長ければ縦を詰める。
- **重心を保つ。** 動かすと構図がずれて合わせ直しになる。
- **ロックの既定は切。** 開き直しただけで保存済みの四隅が書き換わらないようにする。
- **幾何は複製せず `bin/_vce_geometry.py` へ移動。** vce-split へコピーすると、片方だけ直したときに「まとめた版と曲ごとの版で絵が違う」という最も気づきにくい壊れ方をする。chaptr 側は別リポジトリなので共有できず、従来どおり固定値＋実装読み込みで突き合わせる。
- **drawtext はフィルタ列の最後。** `perspective` より前だと字まで台形に歪み、`scale` より前だと字の大きさが出力解像度で変わる。
- **`vce-split` の `textfile=` 方式は変えない。** エスケープの事故が起きない正しいやり方で、drawtext テストが正解側に使っているのがこれ。位置の式だけ共有の `OVERLAY_POSITIONS` から引く。
- **ショートカットは `Ctrl+Alt+S`。** `Ctrl+Shift+S` はスクリーンショット保存が使っており、QAction のショートカットはキーイベントより先に発火して黙って奪う。
- **焼き込みの余白は解像度に比例**（`w*0.035` / `h-th-h*0.06`）。固定画素だと 4K で枠に貼り付く。

### 調べて分かった外部仕様

- **`vce-encode` / `vce-split` の `project` 引数は `.txt` が推奨と表示されるが、`.txt` は補正を運べない。** `load_project_from_txt`（vce-encode 796 行付近）が `{"sources": [source], ...}` と**文字列**で返すため。補正を効かせるには `.vce.json` を渡すしかない。
- **`escape_drawtext` は自分で `'…'` を付けて返し、呼び出し側がもう一度囲んで `text=''…''` にするのが約束。** `tests/test_vce_encode_drawtext.py::test_closes_the_quote_itself` が明文化している。一重にすると `'` や `\` を含む曲名が**エラー無しで空描画**になる（2026-10 の合宿動画で実際に起きた）。
- **`vce-split` は `vce-encode` と別物。** 曲ごとの出力は `vce-split` のみ。`--drop-excluded` を付けないと `--` 区間が直前の曲に併合され、最後の章はソース終端まで伸びる。
- **`.get(key, 既定)` はキーが存在して値が `None` のとき既定を返さない。** chaptr は出力先未指定を `"output_dir": null` と書くので、両ツールで `Path(None)` → `TypeError`。
- **`__file__` は `exec(compile(...), ns)` の名前空間に自動では入らない。** スクリプトが `Path(__file__).resolve().parent` で `sys.path` を足すようになると、ast-exec 方式のテストが全滅する（94 件）。確認: `python3 -m pytest tests/test_vce_encode_transform.py -q`。
- **chaptr の PySide6 テストはサンドボックス内で `Fatal Python error: Aborted`** になる。`dangerouslyDisableSandbox` が要る。既存テストも同様なので今回の変更とは無関係。

### 検討して採らなかった選択肢と理由

- **四隅をそのままに上下へ黒帯を入れる（レターボックス）。** 1920x1034 を 1080 へ収めれば構図を一切削らずに歪みを消せるが、コンサート映像に黒帯が乗る。切り詰めるほうを採った。
- **射影された矩形から実寸比を復元する（焦点距離を未知数に置く Zhang の解法）。** 厳密だが、四隅が長方形に近いと解が不安定になる。今回のような「ほぼ正面」の素材では使いものにならない。`quad_aspect` は上下辺・左右辺の平均を代表値とする近似を採った。
- **vce-split へ幾何を複製する。** 3 つ目の複製になる。移動＋共有に変えた。
- **`git add -p` でコミットを細かく割る。** 対話モードが使えない環境のため、ファイル単位で 2 commit ずつに留めた。

**1. 補正が保存されていなかった（最も重い）**

ログには出るのに消える。`save_project` の呼び出し元を探すと 0 件:


`tests/test_project_transform_roundtrip.py` が `save_project` を直接呼んでテストしていたため、関数の正しさだけが確かめられ、**UI から到達できないことは誰も見ていなかった**。`Ctrl+S` は `.txt` にチャプターだけを書く別経路。

→ File →「Save Project...」を追加。`tests/test_save_project_reachable.py` で到達性を固定。

**2. `vce-split` が開くことすらできない**

```
TypeError: unsupported operand type(s) for /: 'PosixPath' and 'dict'
```

`load_sources` が `self.project_dir / source_name` としており、chaptr が書く `{"path": ..., "transform": {...}}` を受けられない。vce-encode では以前直した同じ穴が残っていた。

**3. `output_dir: null` で両ツールが落ちる**

```
output_dir = Path(self.project.get('output_dir', str(self.project_dir)))
TypeError: argument should be a str or an os.PathLike object …, not 'NoneType'
```

`.get(key, 既定)` はキーが在れば既定を返さない。`self.project.get('output_dir') or self.project_dir` に直し、相対パスの基準も `.vce.json` のある場所に揃えた。

**4. 自分で二重引用の約束を壊した**

共通化の際に `text={escape_drawtext(...)}` と一重にしたところ、既存テストが落ちた。一重版で敵対的な曲名 14 件中 **7 件**（`'` と `\` を含むもの）が落ちることを確認。検査をソース文字列の完全一致から生成結果の画素比較へ改めた。

**5. `__file__` が無くて 94 件がエラー**

```
E   NameError: name '__file__' is not defined
bin/vce-encode:134: NameError
```

6 ファイルのフィクスチャに `ns = {"__file__": str(VCE_ENCODE)}` を与えて解消。

**6. ディスクを 920 MB 食い潰した（私のコマンド指定ミス）**

```
[out#0/mp4] Terminating thread with return code -28 (No space left on device)
```

検証用プロジェクトの最後が `--後` だったのに `--drop-excluded` を付けなかったため、直前の曲に併合されて**11 秒のつもりが終端までの 1:53 を書き出していた**。`vce-split` の挙動は仕様どおり。部分ファイルは削除。**ディスクは 99% 使用（空き 36 GiB）。**

併せて、ログの `[exited with code 0]` を「失敗なのに成功を返す欠陥」と読みかけたが、これは `| tail -6` の終了コードだった。`vce-split` 自身は `return completed == total_segments` で正しく失敗を返す。**パイプで終了コードが隠れる。**
